# Multiplication Mechanisms in the Optical CPU

**Date:** 2026-03-22
**Status:** Code analysis — documents what exists in the codebase

---

## Two Multiplication Approaches

The codebase contains two distinct mechanisms for multiplication. They serve different purposes.

---

## 1. Kerr Mixer (`mul_mixer`) — Single-Trit × Single-Trit

**File:** `Research/programs/ternary_chip_generator.py`, line 461
**GDS Layer:** 7 (MUL mixer region)
**Physical size:** 30 μm long, 0.8 μm wide

### What it is

A straight LiNbO₃ waveguide relying on the χ³ (third-order / Kerr) nonlinearity. Physically, it's just a waveguide — the multiplication happens through intensity-dependent phase modulation and interference.

### How it works

The Kerr effect causes the refractive index to change proportionally to the light intensity:

```
n = n₀ + n₂ × I
```

When two wavelengths co-propagate in the Kerr waveguide:

- **Same sign inputs** (R+R or B+B): Both wavelengths are present with high intensity. Cross-phase modulation shifts their relative phases. Constructive interference at the output selects Blue (+1). This implements (-1)×(-1)=+1 and (+1)×(+1)=+1.

- **Opposite sign inputs** (R+B): The wavelengths interact destructively through cross-phase modulation. The output selects Red (-1). This implements (-1)×(+1)=-1 and (+1)×(-1)=-1.

- **Zero input** (Green): Green (0) carries no information content in the Kerr interaction. No phase shift occurs. Output remains Green (0). This implements 0×anything=0.

### Truth table

```
  A    ×  B    =  Product
  -1 (R) × -1 (R) = +1 (B)   same sign → positive
  -1 (R) ×  0 (G) =  0 (G)   zero kills it
  -1 (R) × +1 (B) = -1 (R)   opposite sign → negative
   0 (G) × any    =  0 (G)   zero kills it
  +1 (B) × -1 (R) = -1 (R)   opposite sign → negative
  +1 (B) ×  0 (G) =  0 (G)   zero kills it
  +1 (B) × +1 (B) = +1 (B)   same sign → positive
```

### Where it's used

- **Systolic array PEs** — each PE does one trit × trit multiply per cycle
- Generated by `ternary_chip_generator.py` when `operation='mul'`

### Validation status

**NOT FDTD validated.** The GDS layout exists. The physics description in the docstring describes the expected behavior. But no Meep FDTD simulation has been run to confirm the Kerr multiplication truth table produces the correct output wavelengths. **This is an open gap.**

## 2. Universal ALU (`universal_alu_mixer`) — Multi-Trit via Log-Domain

**File:** `Research/programs/ternary_chip_generator.py`, line 511
**Physical size:** ~350 μm total path length

### What it is

A reconfigurable ALU that performs all four arithmetic operations (ADD, SUB, MUL, DIV) using only two mixer types (SFG and DFG) plus log/exp converters. MZI switches select the operation.

### How it works

```
  Two paths, selected by MZI switches:

  LINEAR path (ADD/SUB):
    Input ──────────────────→ SFG or DFG mixer ──────────────→ Output

  LOG path (MUL/DIV):
    Input ──→ LOG converter ──→ SFG or DFG mixer ──→ EXP converter ──→ Output
```

**The key insight:** multiplication is addition in the log domain.

```
  ln(A) + ln(B) = ln(A × B)    ← SFG adds logs = multiplies originals
  ln(A) - ln(B) = ln(A ÷ B)    ← DFG subtracts logs = divides originals
```

### Operation selection

| ctrl_path | ctrl_mixer | Operation |
|-----------|------------|-----------|
| LINEAR | SFG | Addition (A + B) |
| LINEAR | DFG | Subtraction (A - B) |
| LOG | SFG | Multiplication (A × B) |
| LOG | DFG | Division (A ÷ B) |

The MZI switches are thermo-optically controlled — electronic signals heat one arm to shift the phase, routing light to the selected path.

### Components

| Component | Function | Size |
|-----------|----------|------|
| MMI 1×2 splitter | Split input to linear and log paths | ~15 μm |
| `optical_log_converter` | Transform to log-domain encoding | 35 μm |
| MZI switches (×4) | Path selection (linear/log, SFG/DFG) | ~80 μm each |
| SFG mixer | Sum-frequency generation (χ²) | 20 μm |
| DFG mixer | Difference-frequency generation (χ²) | 25 μm |
| `optical_exp_converter` | Transform back from log-domain | 35 μm |
| MMI combiners | Merge paths at output | ~15 μm |

### Where it's used

- **General-purpose CPU path** — when the ISA executes MUL (3 cycles) or DIV (5 cycles) on full 81-trit numbers
- The OPU controller configures the MZI switches to select the operation
- NOT used in the systolic array (too complex per PE)

### Log-domain limitation for systolic arrays

Log-domain multiplication outputs a log-domain result. You cannot directly add log-domain partial sums to compute a dot product:

```
  log(a×b) + log(c×d) = log(a×b×c×d)    ← WRONG (product of products)
  
  You need: a×b + c×d                     ← RIGHT (sum of products)
```

For the systolic array, each PE must convert back to linear before accumulating. The Kerr mixer avoids this problem entirely because it outputs in linear domain.

## Summary: Which Mechanism Where

| Context | Mechanism | Cycles | Why |
|---------|-----------|--------|-----|
| Systolic array PE (trit × trit) | Kerr mixer (χ³) | 1 | Simple, direct, output in linear domain |
| CPU ALU (81-trit × 81-trit) | Universal ALU (log-domain) | 3 | Handles full multi-trit numbers |
| CPU ALU (division) | Universal ALU (log-domain DFG) | 5 | Same hardware, different MZI config |

## Open Questions

1. **Kerr mixer FDTD validation** — Has the χ³ multiplication truth table been confirmed in simulation? The SFG mixer is validated; the Kerr mixer is not.

2. **Log converter design** — The `optical_log_converter` component exists in GDS but its physical mechanism (how do you convert a wavelength-encoded value to its logarithm optically?) is not fully documented in the code comments.

3. **Kerr efficiency** — χ³ effects are inherently weaker than χ² (SFG/DFG). What optical power levels are needed for reliable Kerr multiplication? This affects the power budget for the systolic array.
